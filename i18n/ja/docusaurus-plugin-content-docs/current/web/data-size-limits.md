# データ制限

ダウンロードされたファイルのサイズ、結果セット内のセルの数 (集計後)、ピボット テーブルとグリッドのサイズ (セルの数として指定) に関して、Reveal Web を使用する場合のサーバー側のサイズ制限があります。また、Reveal SDK では、クライアント側で 1 つのビジュアライゼーションに要求できるセル数にも制限があります。
これらの制限の目的は、サーバーのリソース (メモリとディスク領域) が不足するのを防ぐことです。

デフォルトの制限値:

-	csv/json/excel をダウンロードする場合は 200 MB
-	1000 万のセル
-	6400 万文字 (すべてのセルのすべての文字列を追加)
-	1 つのビジュアライゼーションに要求できるセル数は 100,000

## デフォルト値を変更

### ソース
[**RevealEmbedSettings**](https://help.revealbi.io/api/aspnet/latest/Reveal.Sdk.RevealEmbedSettings.html)


| プロパティ  |   型| 説明  |  
|---|---|---|
|  MaxDownloadSize | `System.Nullable<System.Int64>`  | 1 回のダウンロード (CSV ファイルなど) のサイズに制限を設定します。デフォルトは 200 MB です。|
|  MaxStorageCells | `System.Nullable<System.Int64>`  | このプロパティを、任意のデータ ソース (SQL Server テーブルの行、CSV 行など) から処理されるセルの予想される最大数に設定します。エンジンは、キャッシュにディスク領域を使いすぎないようにします。この設定は、キャッシュ管理のヒントを提供します。デフォルトは 1000 万セルです。 |
|  MaxStringCellSize | `System.Nullable<System.Int32>`  |  データセット列の文字列が持つことができる文字数の制限を設定します。デフォルトは 256 です。この制限は、グリッドおよびピボットの [PDF エクスポート](https://help.revealbi.io/ja/web/exporting-dashboards/#pdf-へのエクスポート)に表示されるテキストにも適用されます。 |
|  MaxTotalStringsSize | `System.Nullable<System.Int64>`  | このプロパティを、すべてのセルの文字の総数として指定された、ピボット テーブルまたはグリッドの予想される最大サイズに設定します。エンジンはメモリの使用を避け、この設定はメモリ管理のヒントを提供します。デフォルトは 6400 万です。 |

## MaxStringCellSize と PDF エクスポート

`MaxStringCellSize` は、グリッドおよびピボットの [PDF エクスポート](https://help.revealbi.io/ja/web/exporting-dashboards/#pdf-へのエクスポート)に表示されるテキストを制限します。この制限を超える値は切り捨てられるため、エクスポートされた PDF にこの設定で許可された文字数を超えるテキストが表示されることはありません。「無制限」のオプションはありません。

レポートで長いテキストが必要な場合にこの値を大きくしたくなりますが、これはエクスポートの設定ではありません。エンジンはデータをキャッシュに読み込む時点で、つまり表示形式の描画やエクスポートが実行される前にこの設定を適用します。また、これはサーバー全体で 1 つの値であり、ダッシュボードごとやエクスポートごとに上書きすることはできません。この値を大きくすると、サーバー上のすべてのダッシュボードについて、データの取り込みとキャッシュの方法が変わります。

変更する前に、値を大きくすると以下の影響があることにご注意ください。

- エクスポートの対象となるダッシュボードだけでなく、すべてのダッシュボードについて、キャッシュされる各データセットのディスクおよびメモリ上のサイズが増加します。
- `MaxTotalStringsSize` の上限 (デフォルトは 6400 万文字) の消費が比例して速くなります。この上限を超えたデータセットは、段階的に動作が低下するのではなく、**データ サイズ エラーで読み込みに失敗します**。しかもエラーが発生するのは上限を超えたダッシュボードであり、エクスポートを実行したダッシュボードとは限りません。`MaxStringCellSize` を大幅に大きくする場合は、あわせて `MaxTotalStringsSize` も見直してください。
- グリッドおよびピボットのセルは幅が固定されており、長い値は複数行に折り返されるため、エクスポートされる PDF の行の高さとページ数が増加します。

データに適した値の選択はお客様にお任せしています。データに含まれる可能性のある最長の値に合わせるのではなく、エクスポートの可読性を保てる最小限の長さを設定してください。

```cs
builder.Services.AddControllers().AddReveal(revealSetupBuilder =>
{
    revealSetupBuilder.AddSettings(settings =>
    {
        // サーバー全体の設定です。PDF エクスポートだけでなく、すべてのデータ読み込みに影響します。
        settings.MaxStringCellSize = 1024;
        settings.MaxTotalStringsSize = 128000000; // 上記とあわせて見直してください
    });
});
```

:::warning この設定を変更した後はデータ キャッシュをクリアしてください
`MaxStringCellSize` はデータセットのキャッシュ キーに含まれていません。そのため、この設定を変更しても、すでにキャッシュされているデータセットは無効化されません。キャッシュされたデータは変更前の値で切り捨てられており、そのまま再利用されます。キャッシュをクリアするまで、ダッシュボードには切り捨てられた古い値が表示され続け、設定が反映されていないように見えます。

キャッシュをクリアするには、アプリケーションを停止した状態で[キャッシュ ディレクトリ](https://help.revealbi.io/ja/web/caching/#キャッシュ-ファイル) (`CachePath` および `DataCachePath`) の内容を削除してください。表示形式のメニューにある **[更新]** オプションでは不十分です。これは既存のキャッシュに対して 1 つのデータ ソースを更新するだけであり、変更前の制限でキャッシュされたデータセットを破棄するものではありません。
:::

レポート 1 つだけで長いテキストが必要な場合は、グローバルな制限を大きくするのではなく、長い列を分割する、クエリ内で切り詰めるなど、データ側の見直しを検討してください。

## クライアント側のビジュアライゼーション制限

`RevealSdkSettings.maxCellsRestriction` は、1 つのビジュアライゼーションでデータ ソースに要求できるセル数 (行 * 列) の上限を制御します。デフォルトは 100,000 です。`RevealView` を作成する前に設定してください。

```ts
import { RevealSdkSettings } from "reveal-sdk";

RevealSdkSettings.maxCellsRestriction = 200000;
```

この値を増やすと、ビジュアライゼーションでより多くのデータを表示できますが、メモリ使用量が増加し、パフォーマンスが低下する可能性があります。

# データ制限

ダウンロードされたファイルのサイズ、結果セット内のセルの数 (集計後)、ピボット テーブルとグリッドのサイズ (セルの数として指定) に関して、Reveal Web を使用する場合のサーバー側のサイズ制限があります。また、Reveal SDK では、クライアント側で 1 つのビジュアライゼーションに要求できるセル数にも制限があります。
これらの制限の目的は、サーバーのリソース (メモリとディスク領域) が不足するのを防ぐことです。

デフォルトの制限値:

-	csv/json/excel をダウンロードする場合は 200 MB
-	1000 万のセル
-	6400 万文字 (すべてのセルのすべての文字列を追加)
-	1 つのビジュアライゼーションに要求できるセル数は 100,000

## デフォルト値を変更

### ソース
[**RevealEmbedSettings**](https://help.revealbi.io/api/aspnet/latest/Reveal.Sdk.RevealEmbedSettings.html)


| プロパティ  |   型| 説明  |  
|---|---|---|
|  MaxDownloadSize | `System.Nullable<System.Int64>`  | 1 回のダウンロード (CSV ファイルなど) のサイズに制限を設定します。デフォルトは 200 MB です。|
|  MaxStorageCells | `System.Nullable<System.Int64>`  | このプロパティを、任意のデータ ソース (SQL Server テーブルの行、CSV 行など) から処理されるセルの予想される最大数に設定します。エンジンは、キャッシュにディスク領域を使いすぎないようにします。この設定は、キャッシュ管理のヒントを提供します。デフォルトは 1000 万セルです。 |
|  MaxStringCellSize | `System.Nullable<System.Int32>`  |  データセット列の文字列が持つことができる文字数の制限を設定します。デフォルトは 256 です。この制限を超える値は、ダッシュボード上でも [PDF エクスポート](https://help.revealbi.io/ja/web/exporting-dashboards/#pdf-へのエクスポート)でも同様に切り捨てられます。[MaxStringCellSize と長いテキスト値](#maxstringcellsize-と長いテキスト値)を参照してください。 |
|  MaxTotalStringsSize | `System.Nullable<System.Int64>`  | このプロパティを、すべてのセルの文字の総数として指定された、ピボット テーブルまたはグリッドの予想される最大サイズに設定します。エンジンはメモリの使用を避け、この設定はメモリ管理のヒントを提供します。デフォルトは 6400 万です。 |

## MaxStringCellSize と長いテキスト値

`MaxStringCellSize` は、エンジンがデータを読み込む際に文字列値を何文字まで保持するかを決定します。この制限を超える値は制限の長さに切り捨てられ、製品のすべての箇所が同じ切り捨て後の値を使用します。つまり、ダッシュボード上のグリッドおよびピボットの表示形式でも、それらの [PDF エクスポート](https://help.revealbi.io/ja/web/exporting-dashboards/#pdf-へのエクスポート)でも同じです。「無制限」のオプションはありません。

そのため、PDF エクスポートのテキスト長は、ダッシュボードに表示される内容と常に一致します。PDF のセルにより多くの文字を表示したい場合は `MaxStringCellSize` を大きくしてください。その場合、ダッシュボードにも同じく長いテキストが表示されます。

この設定はデータ読み込み時にサーバー全体に対して一度だけ適用されます。ダッシュボードごとやエクスポートごとのオプションではありません。値を大きくするとサーバー上のすべてのダッシュボードに影響するため、変更する前に以下をご検討ください。

- 文字列が長くなると、`MaxTotalStringsSize` の上限 (デフォルトは 6400 万文字) の消費が比例して速くなります。この上限を超えたデータセットは、段階的に動作が低下するのではなく、**データ サイズ エラーで読み込みに失敗します**。`MaxStringCellSize` を大幅に大きくする場合は、あわせて `MaxTotalStringsSize` も見直してください。
- グリッドおよびピボットのセルは幅が固定されているため、長い値は複数行に折り返されます。PDF エクスポートでは、これにより行の高さとページ数が増加します。

データに含まれる可能性のある最長の値に合わせるのではなく、データの可読性を保てる最小限の長さを設定してください。Reveal は分析ツールであり、その表示形式は集計値や短いラベルを前提に設計されています。段落単位のテキストを含む列は、通常、分割する、クエリ内で短縮する、または表示形式に含めないようにすることをおすすめします。

```cs
builder.Services.AddControllers().AddReveal(revealSetupBuilder =>
{
    revealSetupBuilder.AddSettings(settings =>
    {
        // サーバー全体の設定です。すべてのダッシュボードのデータ読み込みに適用されます。
        settings.MaxStringCellSize = 1024;
        settings.MaxTotalStringsSize = 128000000; // 上記とあわせて見直してください
    });
});
```
## クライアント側のビジュアライゼーション制限

`RevealSdkSettings.maxCellsRestriction` は、1 つのビジュアライゼーションでデータ ソースに要求できるセル数 (行 * 列) の上限を制御します。デフォルトは 100,000 です。`RevealView` を作成する前に設定してください。

```ts
import { RevealSdkSettings } from "reveal-sdk";

RevealSdkSettings.maxCellsRestriction = 200000;
```

この値を増やすと、ビジュアライゼーションでより多くのデータを表示できますが、メモリ使用量が増加し、パフォーマンスが低下する可能性があります。
